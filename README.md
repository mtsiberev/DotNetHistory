# DotNetHistory

DotNetHistory — это интерактивное веб-приложение и база знаний, собирающая хронологию и ключевые изменения в экосистеме .NET (Framework 4.7.1+, Core 1.0–3.1, .NET 5–10).

Проект спроектирован в виде интерфейса Master-Detail (две независимые колонки) и оснащен интерактивной песочницей, позволяющей не просто читать код, но и видеть реальный результат его выполнения на сервере (вывод консоли) без использования тяжелой рефлексии и просадки производительности.

---

## Стек технологий

*   Платформа: .NET 8.0 / 9.0 / 10.0
*   Интерфейс: Blazor Web App (Режим рендеринга InteractiveServer)
*   Стилизация: Bootstrap 5 (с адаптивной двухколоночной сеткой)
*   Архитектура данных: Разделение данных (JSON) и исполняемой логики (Реестр фабрик)

---

## Архитектура проекта и структура папок

Проект разделен на изолированные слои, обеспечивающие высокую производительность и полную готовность к Native AOT компиляции:

*   wwwroot/data/features.json — единая база данных справочника (хронология, названия фич и текстовые описания).
*   Models/ — строго типизированные C#-модели (DotNetVersion, FeatureItem) для безопасной десериализации JSON.
*   Services/
    *   IFeatureService.cs — контракт сервиса для взаимодействия UI и бизнес-логики.
    *   MockFeatureService.cs — отвечает за асинхронное чтение JSON с диска и подтягивание живого исходного кода из файлов примеров.
    *   FeatureRegistry.cs — строго типизированный реестр (хэш-таблица), связывающий строковый Id фичи с фабрикой делегатов Func<IFeatureRunner>. Обеспечивает мгновенный вызов кода без Reflection.
*   FeatureExamples/ — папка с изолированными C#-файлами примеров. Каждый класс реализует интерфейс IFeatureRunner и перехватывает вывод консоли через подмену потока Console.SetOut.
*   Components/Pages/Catalog.razor — главный экран приложения. Колонки зафиксированы по высоте экрана (height: calc(100vh - 80px)) и имеют независимый скролл.

## Быстрый запуск

### Системные требования
*   Установленный .NET SDK 8.0 / 9.0 / 10.0.
*   IDE (Visual Studio 2022 / VS Code / JetBrains Rider).

### Запуск через терминал (.NET CLI)
1.  Перейдите в корневую директорию проекта:
    ```bash
    cd DotNetHistory
    ```
2.  Восстановите зависимости и запустите приложение:
    ```bash
    dotnet run
    ```
3.  Откройте браузер по адресу, указанному в консоли (обычно https://localhost:7001), и перейдите во вкладку "История .NET".

## Инструкция: Как добавить новую живую фичу

Чтобы расширить базу знаний и добавить новую фичу с исполняемым кодом, необходимо выполнить 3 шага:

1.  В JSON (wwwroot/data/features.json): Добавить элемент в массив нужной версии .NET, указав уникальный Id, Name и Description. Поле CodeExample оставить пустым.
2.  В C# класс (FeatureExamples/): Создать новый класс примера (например, MyNewFeatureExample.cs), реализовать в нем интерфейс IFeatureRunner и поместить исполняемый код внутрь метода Execute(), используя перехват Console.SetOut. В свойствах файла выставить Copy to Output Directory = Copy if newer.
3.  В Реестр (Services/FeatureRegistry.cs): Добавить одну строчку в словарь Runners, связав Id из JSON с конструктором нового класса: { "my-feature-id", () => new MyNewFeatureExample() }.
